## Что такое Surgical Simulation

Модуль Surgical Simulation — инструмент визуализации предполагаемого результата пластической операции на фотографии пациента до вмешательства. Вы загружаете фото, расставляете контрольные точки в зонах предстоящей коррекции, перетаскиваете их в желаемую позицию — изображение деформируется в реальном времени, показывая ожидаемый результат.

Инструмент работает на базе 2D-деформации (liquify / mesh warp) с применением Radial Basis Function и Gaussian-фильтра. Все вычисления выполняются в браузере с использованием WebWorker'а, данные пациента не покидают ваше устройство до момента сохранения плана на защищённый сервер DocPats.

**Используйте этот модуль для:**

- Консультации с пациентом перед принятием решения об операции
- Уточнения ожиданий (expectation management)
- Документирования предоперационного плана
- Создания визуального материала для согласия пациента (informed consent)
- Внутреннего обсуждения вариантов в команде клиники

**Модуль не заменяет:**

- Клиническую оценку пациента
- Рентгенологическое планирование
- 3D-сканирование (если есть показания)
- Юридически значимое медицинское заключение

Результат симуляции — это **ориентировочная визуализация**, не гарантия конкретного исхода операции.

## Рабочий процесс за 2 минуты

**Шаг 1.** Главное меню → "Симуляция" → кнопка `+ Новый план` в правом верхнем углу.

**Шаг 2.** В открывшемся окне перетащите фото пациента или нажмите область загрузки. Допустимые форматы: JPG, PNG, WebP. Максимальный размер: 20 MB. Минимальное разрешение: 200×200 px.

**Шаг 3.** На шаге 2 модального окна введите название плана (например: "Иванов И.А. — ринопластика, вариант 1") и, опционально, идентификатор пациента. Нажмите "Создать".

**Шаг 4.** Откроется редактор. Переключите режим на "Добавить точку" (иконка `+●` в верхней панели). Кликните в зонах предстоящей коррекции — появятся контрольные точки.

**Шаг 5.** Переключитесь в режим "Выбор" (иконка стрелки-курсора). Перетащите синий круг каждой точки в желаемую позицию. Изображение деформируется в реальном времени.

**Шаг 6.** Когда результат соответствует плану операции — переключитесь на вкладку "До / После" в правом верхнем углу. Слайдер показывает сравнение.

**Шаг 7.** В панели "Экспорт" выберите формат (JPG/PNG), режим (до / после / side-by-side) и нажмите "Скачать". Файл сохранится локально.

Все изменения сохраняются автоматически каждые 2 секунды. Индикатор сохранения расположен в правой части toolbar'а.

## Создание нового плана

### Именование плана

Название плана будет зашифровано в базе данных и доступно только вам. Рекомендуемая структура имени:

`[Фамилия И.О.] — [тип операции], [вариант]`

Примеры:

- `Петрова А.Б. — ринопластика, консервативный`
- `Петрова А.Б. — ринопластика, агрессивный`
- `Сидоров В.К. — blepharoplasty, оба глаза`

Создавайте несколько планов для одного пациента, если обсуждаете **варианты** — консервативный / умеренный / агрессивный. Это позволит пациенту сравнить их на консультации.

### Идентификатор пациента

Поле опциональное. Можно использовать:

- Номер медицинской карты клиники
- Инициалы
- Внутренний код

Это поле также шифруется. Не используйте полное ФИО если клиника работает под требованиями GDPR/HIPAA — достаточно номера карты.

### Поиск и сортировка планов

В списке планов доступны:

- **Поиск** по названию или идентификатору пациента (регистр не учитывается)
- **Сортировка**: от новых к старым, от старых к новым, по алфавиту

## Требования к фотографии пациента

От качества входного фото критически зависит точность симуляции.

### Обязательные условия

**Разрешение.** Минимум 1000×1500 px по короткой стороне. Оптимально 2000×3000 px. Фото смартфона в обычном режиме подходит. Селфи и web-cam фото использовать не рекомендуется из-за искажения перспективы широкоугольным объективом.

**Освещение.** Равномерное с фронта, без резких теней на лице. Избегайте bright sunlight контрового освещения. Оптимально — студийный softbox или рассеянный дневной свет в окне.

**Расстояние до камеры.** Не ближе 1.5 метров. Это минимизирует perspective distortion носа и подбородка. Используйте 50-85 мм focal length эквивалент (на iPhone — не wide, а telephoto объектив 2×).

**Нейтральное выражение лица.** Пациент не улыбается, губы сомкнуты, но не сжаты. Глаза открыты, смотрят в камеру. Никаких мимических сокращений.

**Волосы.** Убраны от лица. Не закрывают лоб, уши, линию подбородка. В идеале — собраны сзади.

**Украшения и макияж.** Удалены. Пирсинг, крупные серьги, яркая помада — всё искажает референс.

**Нейтральный фон.** Светлый однотонный (серый, белый, бледно-голубой). Никаких паттернов, текстур, ярких объектов за головой.

### Ракурсы

Для полноценного планирования желательно иметь три фото одного пациента:

1. **Frontal** (анфас) — для оценки симметрии, ширины крыльев носа, формы губ
2. **Profile** (профиль, левый и правый) — для оценки угла, спинки, кончика носа, подбородка
3. **3/4** (полупрофиль) — для оценки объёма средней зоны, скул

**Важно:** в текущей версии (MVP) каждое фото = отдельный план. В следующей версии (v2) планируется multi-view в рамках одного плана.

### Что делать, если фото не соответствует требованиям

Не загружайте его. Попросите пациента переснять или пересниимите сами в клинике. Деформация на плохом фото даёт ложные ожидания, что ведёт к конфликту после операции.

## Интерфейс редактора

### Заголовок страницы

- **Стрелка "← К списку планов"** — возврат к списку всех планов.
- **Название плана и ID пациента** — отображаются под стрелкой.
- **Вкладки "Редактор / До-После"** — переключение режима работы.

### Верхняя панель редактора (toolbar)

Расположена в правом верхнем углу canvas'а. Элементы слева направо:

**1. Режим "Выбор"** (иконка стрелки-курсора). Активный — подсвечен синим. В этом режиме:

- Клик по фону canvas'а и тяга — панорамирование (pan)
- Клик по синему кругу точки — выделение + перетаскивание (drag)
- Клик по жёлтому квадрату — выделение точки
- Alt + тяга жёлтого квадрата — перемещение anchor'а

**2. Режим "Добавить точку"** (иконка `+●`). Активный — синий. В этом режиме клик по фото создаёт новую контрольную точку.

**3. Undo / Redo** (иконки ↶ / ↷). Отмена и возврат последнего действия. Неактивны если отменять нечего. Hotkey: Ctrl+Z / Ctrl+Shift+Z (Ctrl+Y).

**4. Zoom −** / процент / **Zoom +**. Уменьшение и увеличение масштаба. Текущий процент отображается в середине. Также доступно колесом мыши — zoom привязан к курсору (как в Figma).

**5. "Fit"** — подогнать фото под размер canvas'а.

**6. "1:1"** — сбросить zoom до 100%, центрировать фото.

**7. Индикатор сохранения** — последний элемент справа:

- `●` синий пульсирующий — идёт сохранение
- `✓` зелёный — сохранено
- `✕` красный — ошибка сохранения (проверить интернет)

### Нижняя информационная полоса

В левом нижнем углу показывает:

- Разрешение фото (пример: `677×1200`)
- Количество точек деформации

### Панель свойств точки

Появляется в правом нижнем углу при выделении любой точки. Содержит:

- **Radius (Радиус влияния)** — слайдер 1–50%. Определяет зону деформации вокруг точки. Чем меньше radius, тем локальнее изменение. Значение показано в процентах от длинной стороны изображения. Пунктирная окружность на canvas'е визуализирует radius.

- **Strength (Сила)** — слайдер от −1.00 до +1.00. При 1.00 точка тянет пиксели в сторону смещения с полной силой. При 0.50 — половина. При отрицательных значениях точка **отталкивает** пиксели от смещения (используется для коррекции-обратных эффектов).

- **Крестик × в заголовке** — удаление точки.

- **Подсказки** внизу панели:
  - `Alt + перетаскивание квадрата — сдвиг центра`
  - `Del — удалить`

## Работа с контрольными точками

### Анатомия контрольной точки

Каждая точка состоит из четырёх элементов:

1. **Жёлтый квадрат (Anchor)** — исходный центр деформации. Обычно совпадает с местом первоначального клика. По умолчанию не двигается.

2. **Синий круг (Current)** — целевая точка. То, куда вы "хотите переместить" пиксель, находящийся в позиции anchor'а. Это основной элемент для перетаскивания.

3. **Пунктирная линия** между anchor и current — вектор смещения. Показывает направление и величину деформации.

4. **Пунктирная окружность вокруг anchor'а** — зона влияния точки. Чем дальше пиксель от центра, тем меньше его смещение. За пределами окружности — деформации нет.

### Добавление точек

1. Переключитесь в режим `+●`.
2. Кликайте в зонах, где планируется коррекция. Каждый клик создаёт новую точку.
3. При создании точка имеет anchor = current (то есть смещения ноль). Radius по умолчанию 8%, strength 1.00.

### Перемещение точки

1. Переключитесь в режим "Выбор".
2. Зажмите левой кнопкой мыши синий круг и перетащите в желаемую позицию.
3. Фото деформируется в реальном времени по мере движения.

### Тонкая настройка

1. Выделите точку (клик на синий круг или жёлтый квадрат).
2. В правой нижней панели отредактируйте:
   - Radius — ширина зоны влияния
   - Strength — сила деформации

### Удаление точки

Три способа:

- Выделить точку → нажать × в панели свойств
- Выделить точку → Delete или Backspace на клавиатуре
- Выделить точку → Escape сбрасывает выделение (не удаляет)

### Лимит точек

Технический максимум — 200 точек на план. На практике для качественной ринопластики достаточно 10–25 точек, для более сложных вмешательств (полная реконструкция лица) — до 50–70.

## Продвинутые техники деформации

Текущий MVP-движок использует глобальную RBF-деформацию. Это даёт хорошие результаты для локальных изменений, но требует определённой техники для точного управления.

### Техника 1 — Малые точки для локальных изменений

Проблема: большой radius деформирует не только целевую зону, но и соседние структуры. Решение — использовать маленький radius (2-4%) для точных изменений.

**Пример: снятие горбинки носа**

1. Создайте точку прямо на вершине горбинки.
2. Установите radius = 2-3%.
3. Strength = 1.00.
4. Перетащите синий круг **вертикально вниз** на 3-5 пикселей.
5. Горбинка сглаживается, соседние части спинки носа почти не двигаются.

### Техника 2 — Цепочки точек вдоль линии

Проблема: одна точка даёт круглое (радиальное) искажение. Для коррекции **линейной** структуры (спинка носа, линия подбородка, губная линия) нужна цепочка точек.

**Пример: выпрямление спинки носа**

1. Создайте 4-5 точек вдоль спинки носа с интервалом 10-15% от длины носа.
2. Каждая точка — radius 2-3%.
3. Перетащите синие круги так, чтобы они выстроились по желаемой прямой линии.
4. Результат: спинка носа спрямлена, остальное лицо не затронуто.

### Техника 3 — Якорные точки (anchors)

Проблема: при деформации одной зоны смежная (например, щёки рядом с носом) тоже немного двигается из-за распространения RBF-поля.

Решение — поставить **якорные точки** по периметру зоны коррекции. У якорных точек anchor = current (синий круг не перемещается), но они присутствуют в warp-расчёте и удерживают соседние пиксели от движения.

**Пример: коррекция кончика носа без движения губ**

1. Создайте рабочую точку на кончике носа, radius 5%, перетащите вверх.
2. Создайте якорную точку на филтруме (между носом и губой), radius 4%, **не двигайте**.
3. Создайте якорные точки по обе стороны крыльев, radius 3%, **не двигайте**.
4. Кончик носа поднят, филтрум и губа остались на месте.

### Техника 4 — Отрицательный strength для "раздувания"

Иногда нужно не сдвинуть точку, а "раздуть" область (шире крылья носа, полнее губы).

1. Создайте точку в центре желаемой зоны расширения.
2. Перетащите синий круг **за пределы** желаемой границы.
3. Установите strength **−0.3 до −0.5** (отрицательное значение).
4. Radius = 5-10%.
5. Зона отталкивается от точки = эффект расширения.

### Техника 5 — Множественные варианты через дубликаты

Для консультации удобно иметь несколько вариантов одной и той же операции. Используйте функцию "Дублировать" в списке планов:

1. Создайте план "Петрова А.Б. — ринопластика, вариант 1 (консервативный)".
2. Отредактируйте: малые смещения, тонкие изменения.
3. В списке планов → кнопка "Копировать" на этом плане.
4. Переименуйте дубликат: "Петрова А.Б. — ринопластика, вариант 2 (умеренный)".
5. Откройте, усильте деформации.
6. Повторите для "вариант 3 (агрессивный)".

На консультации показывайте пациенту все три варианта последовательно.

### Чего избегать

**Не используйте огромные radius + огромные смещения одновременно.** Это создаёт волновые артефакты на фоне и линии волос.

**Не деформируйте фон.** Если линия волос / ухо / плечо попадают в radius — они тоже искажаются. Ставьте якорные точки вокруг чтобы "запереть" фон.

**Не работайте с сильным зумом out.** Точная постановка точек требует zoom 100% или больше. Используйте `+` и `1:1` на toolbar'е.

**Не игнорируйте симметрию.** Если пациент просит коррекцию носа — деформируйте обе стороны согласованно. В текущем MVP это делается вручную (mirror mode появится в v2).

## Консультация с пациентом

Вкладка "До / После" предназначена для **показа пациенту**. На ней минимум технических элементов, максимум визуального сравнения.

### Слайдер-разделитель

Центральное изображение разделено вертикальной линией с круглой ручкой. Перетаскивая её влево-вправо, пациент видит:

- Левая часть — фото "До" (оригинал)
- Правая часть — фото "После" (с деформацией)

В углах подписи "ДО" и "ПОСЛЕ" чтобы не было путаницы.

### Рекомендуемый сценарий консультации

1. Откройте план в fullscreen (F11 в браузере для полного экрана).
2. Покажите пациенту вкладку "Редактор" — объясните что именно планируете менять, используя сами точки как визуальные маркеры.
3. Переключитесь на "До / После", дайте пациенту самому поводить слайдер.
4. Обсудите — соответствует ли это его ожиданиям.
5. Если есть другие варианты (консервативный / агрессивный) — закройте текущий, откройте следующий план.
6. По итогу выберите один вариант как финальный.
7. Экспортируйте в PDF (или JPG+печать) для приложения к информированному согласию.

### Что важно сказать пациенту

Симуляция — это **визуализация ожидаемого результата, не гарантия**. Реальный исход операции зависит от:

- Индивидуальных особенностей тканей (толщина кожи, эластичность, толщина хрящей)
- Процесса заживления и рубцевания
- Техники хирурга
- Соблюдения пациентом послеоперационного режима

Отклонения в ±10-20% от симуляции — нормальны и не являются дефектом операции. Используйте эту фразу в информированном согласии.

## Экспорт и документация

### Панель "Экспорт"

Расположена справа на вкладке "До / После".

### Что экспортировать

**1. До операции (оригинал)** — исходное фото пациента без деформаций. Используется для medical record, для "факт до" в сравнении с результатом.

**2. После операции (с деформацией)** — фото с применённым warp'ом. Используется для показа пациенту, для документации плана.

**3. Рядом: До и После** — side-by-side композиция в одном изображении с подписями "ДО" и "ПОСЛЕ". Самый удобный формат для распечатки и для информированного согласия.

### Формат

**JPG** — рекомендуется для большинства случаев. Малый вес, приемлемое качество при 85-92%.

**PNG** — без сжатия, максимальное качество. Используйте если результат будет дальше редактироваться в Photoshop или печататься в большом формате.

### Качество JPG

Слайдер 40-100%. Рекомендации:

- 60-70% — для email, мессенджеров
- 80-90% — стандарт для document print
- 95-100% — для архива, публикации

### Скачивание

После настройки параметров нажмите "Скачать". Файл сохранится в папку Downloads вашего браузера с именем вида `plan-2026-04-24-ринопластика.jpg`.

### Рекомендация по документированию

Для каждой операции сохраняйте в электронную карту пациента:

1. Оригинальное фото (экспорт "До")
2. Симуляцию результата (экспорт "После")
3. Side-by-side (экспорт "Рядом")
4. Скриншот редактора с видимыми контрольными точками (через Print Screen) — для понимания того, что именно было спланировано

Это создаёт полную документацию pre-op планирования и защищает от post-op споров с пациентом.

## Сохранение, дубликаты, удаление

### Автосохранение

Все изменения (добавление/удаление точек, изменение их параметров, перетаскивание) сохраняются **автоматически через 2 секунды** после последнего действия. Вручную ничего делать не нужно.

Индикатор сохранения в верхнем toolbar'е показывает текущий статус:

- `●` синий пульсирующий — идёт сохранение
- `✓` зелёный — сохранено
- `✕` красный — ошибка (проверьте интернет-соединение)

При закрытии страницы или переходе на другую вкладку — форсированное сохранение. Данные не теряются.

### Дублирование плана

В списке планов у каждой карточки три кнопки: "Открыть", "Копировать", "Удалить".

**Копировать** создаёт полный дубликат плана с тем же фото и всеми контрольными точками. Дубликат появляется сверху списка. Переименуйте его перед редактированием (например, добавьте "(вариант 2)" к имени).

Используется для:

- Создания нескольких вариантов операции
- Backup'а плана перед экспериментальными изменениями
- Переноса настроек на схожую анатомию

### Удаление плана

Кнопка "Удалить" запрашивает подтверждение. После подтверждения:

- План помечается как удалённый в БД (soft delete)
- Фото пациента удаляется из R2-хранилища через 24 часа (если на это фото нет других ссылок из дубликатов)
- План исчезает из списка

**Внимание:** отменить удаление нельзя. Если нужна страховка — дублируйте план перед удалением оригинала.

## Конфиденциальность и PHI

DocPats Surgical Simulation разработан с учётом требований HIPAA (США) и GDPR (ЕС) в отношении медицинских данных пациентов.

### Что шифруется

- **Название плана** — AES-256-GCM, шифруется в БД
- **Идентификатор пациента** — AES-256-GCM, шифруется в БД
- **Фотография** — хранится в R2 с серверным шифрованием, доступ только по авторизованной session

### Что не шифруется

- Контрольные точки (координаты, radius, strength) — это не PHI в понимании HIPAA, так как не идентифицируют пациента отдельно от фото и метаданных
- Даты создания/обновления плана

### Доступ

- Только вы как владелец аккаунта DocPats имеете доступ к своим планам
- Ни Anthropic, ни DocPats team не может прочитать содержимое ваших планов
- В случае требования суда — предоставляются зашифрованные данные, ключ остаётся у клиники

### Рекомендации

**Используйте сложные пароли и 2FA для DocPats-аккаунта.** Взлом вашего аккаунта = компрометация PHI пациентов.

**Не сохраняйте скриншоты на незащищённый local disk** без PIN/password. Экспортированные JPG/PNG не шифруются автоматически.

**Перед утилизацией компьютера клиники** убедитесь что браузерный cache не содержит копий фото. Используйте browser privacy tools (например, Cleanup Cache в Chrome).

**При работе с европейскими пациентами** (GDPR) — запрашивайте письменное согласие на обработку биометрических данных **до** загрузки фото в систему.

## Решение проблем

### Фото не загружается, появляется "Görsel okunamadı" или "Image cannot be read"

**Причина 1:** Формат не поддерживается. Поддерживаются только JPG, PNG, WebP. HEIC (iPhone native) **не работает**.

**Решение:** Конвертируйте HEIC в JPG (Photos на Mac, онлайн-конвертер).

**Причина 2:** Фото меньше 200×200 px.

**Решение:** Используйте оригинальное фото, а не thumbnail или preview.

**Причина 3:** Файл повреждён или это не real image (например, .jpg переименованный из .docx).

**Решение:** Откройте файл в штатном просмотрщике (Photos, Preview). Если не открывается — файл битый, используйте другой.

### Editor загружается, но canvas пустой

**Причина:** CORS-ошибка при загрузке фото из R2-хранилища. Обычно происходит при первой загрузке, когда Cloudflare ещё не закешировал правильные headers.

**Решение:** Подождите 30 секунд, сделайте Hard Refresh (Ctrl+Shift+R). Если не помогает — сообщите техподдержке DocPats.

### Точки появляются, но не перетаскиваются

**Причина:** Браузер не получает pointer capture events. Чаще всего это старый браузер или специфичная настройка tablet/stylus.

**Решение:** Обновите браузер до последней версии (Chrome 120+, Firefox 115+, Edge 120+, Safari 17+). На touchpad — используйте мышь.

### Деформация не применяется к фото (точки двигаются, но фото неизменно)

**Причина:** WebWorker не загружен. Chrome может блокировать worker при низкой памяти устройства.

**Решение:** Закройте лишние вкладки, перезагрузите editor (F5). Если повторяется — используйте другой браузер или компьютер с 8GB+ RAM.

### Индикатор сохранения красный (✕)

**Причина:** Нет соединения с сервером DocPats, или session истекла.

**Решение:** Проверьте интернет. Если всё нормально — перезагрузите страницу (изменения за последние 2 секунды могут потеряться, всё остальное сохранено).

### Список планов пустой хотя я создавал планы

**Причина:** Вы залогинены под другим аккаунтом, или случайно переключились на dev/staging среду.

**Решение:** Проверьте URL (должен быть production-URL клиники) и email в настройках аккаунта.

### Фото экспортируется в низком разрешении

**Причина:** Вы используете preview-версию фото (1200 px max), а не full-resolution оригинал.

**Решение:** При экспорте система автоматически применяет warp к полному разрешению — дождитесь пока индикатор загрузки исчезнет (в правом верхнем углу панели экспорта). Не нажимайте "Скачать" пока не дождётесь.

### Editor работает медленно, лагает

**Причина:** На планы с 50+ точками и фото 4000×6000 px деформация становится тяжёлой для low-end устройств.

**Решение:**

- Работайте в режиме Fit (меньший preview вычислительно дешевле)
- Уменьшите количество точек (объединяйте близкие)
- Используйте устройство с dedicated GPU

## Рекомендации по workflow

Из практики использования, оптимальный workflow для консультации:

### До прихода пациента (10-15 минут)

1. Откройте фото пациента (полученное по email заранее или снятое на предварительном визите).
2. Создайте 2-3 плана-варианта в DocPats:
   - `[Пациент] — консервативный`
   - `[Пациент] — умеренный`
   - `[Пациент] — агрессивный`
3. Предварительно расставьте точки в каждом, сохраните.

### Во время консультации (30-40 минут)

1. Объясните пациенту возможности и ограничения операции без визуализации.
2. Откройте DocPats на большом мониторе (минимум 24").
3. Покажите **редактор** с расставленными точками — объясните анатомию.
4. Переключитесь на **До/После** — дайте пациенту поиграть со слайдером.
5. Показывайте **все 3 варианта** последовательно. Дайте 5-10 минут на обсуждение каждого.
6. Обсудите ожидания, сомнения пациента.
7. Выберите финальный вариант совместно.

### После консультации (5 минут)

1. Экспортируйте финальный план в 3 форматах (до / после / side-by-side) в JPG 90%.
2. Сохраните в electronic medical record пациента.
3. Распечатайте side-by-side для физической папки пациента.
4. Приложите к информированному согласию с подписью пациента: "_Я видел симуляцию ожидаемого результата и понимаю, что это приблизительная визуализация_".
5. В день операции (или за день до) — откройте финальный план в DocPats для свежего повторного просмотра с командой.

## Дорожная карта версий

Текущая версия (MVP) — базовый набор функций.

### v2.0 "Assisted" (планируется ближайшие 3-4 недели)

- **Автоматическая разметка лица** через MediaPipe Face Mesh — 468 anatomical landmarks появляются автоматически при открытии плана
- **Группы точек** — показывать/скрывать нос / губы / глаза / брови отдельно
- **Калибровка** — указать расстояние между зрачками, получать все измерения в миллиметрах
- **Медицинские измерения** — nasofrontal angle, nasolabial angle, tip projection (Goode's ratio), alar base width
- **Symmetry lock** — зеркалирование правой половины на левую
- **Nasal surgery presets** — pre-configured наборы точек для hump reduction / tip refinement / nostril narrowing
- **Mask protection** — deformation не затрагивает волосы и фон автоматически

### v3.0 "Professional"

- **Liquify brush** — интерактивный Photoshop-style инструмент в дополнение к точкам
- **Reference library** — база "целевых носов" для быстрого matching
- **Multi-view** — 3-5 ракурсов в одном плане, синхронная деформация
- **PDF-отчёт** для пациента с логотипом клиники, measurements, consent text
- **Consultation mode** — fullscreen UI для презентации

### v4.0 "3D"

- 2D→3D reconstruction через ML
- 3D mesh editing
- AR preview на смартфоне пациента
